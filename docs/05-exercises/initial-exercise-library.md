# Biblioteca inicial de ejercicios FORJA

## Propósito

Definir el primer conjunto controlado de ejercicios que formará la biblioteca práctica de FORJA.

LIB-001 no pretende recopilar todos los ejercicios útiles posibles.

Pretende seleccionar:

> **el conjunto mínimo suficientemente amplio para comprobar que la metodología FORJA puede convertirse en sesiones y programas reales.**

La biblioteca inicial debe permitir aplicar:

- [PAT-001](../04-movement-patterns/movement-pattern-model.md) — Modelo de patrones de movimiento FORJA;
- [EX-STD-001](exercise-card-standard.md) — Estándar de ficha de ejercicio FORJA;
- [MET-001](../03-methodology/initial-athlete-assessment.md) — Evaluación;
- [MET-002](../03-methodology/progression-system.md) — Progresión;
- [MET-003](../03-methodology/session-construction.md) — Construcción de sesiones;
- [MET-004](../03-methodology/dosage-and-prescription.md) — Dosificación;
- [MET-005](../03-methodology/weekly-planning-and-sport-integration.md) — Planificación semanal.

No buscamos cantidad.

Buscamos:

> **cobertura + utilidad + relaciones + capacidad de decisión.**

---

# 1. Principio fundamental

La primera biblioteca FORJA no será:

> una colección de ejercicios interesantes.

Será:

> **un conjunto pequeño de tareas elegidas deliberadamente para construir y validar el sistema.**

Cada ejercicio debe justificar su presencia.

No se incorporará una tarea únicamente porque:

- sea popular;
- aparezca en redes sociales;
- parezca avanzada;
- se utilice en fútbol profesional;
- utilice material sofisticado;
- tenga un nombre atractivo.

La pregunta será:

> **¿qué aporta esta tarea que necesitamos representar en la biblioteca inicial?**

---

# 2. Por qué comenzar con una biblioteca pequeña

Una biblioteca muy grande desde el principio generaría varios problemas:

- duplicados;
- variantes casi idénticas;
- progresiones incoherentes;
- fichas incompletas;
- dificultad para revisar calidad;
- exceso de decisiones sin validar.

FORJA comenzará con una biblioteca pequeña.

Después aprenderemos utilizándola.

Si aparecen necesidades reales:

> la biblioteca crecerá.

---

# 3. Objetivo de esta primera biblioteca

La biblioteca inicial debe permitir construir al menos:

- una sesión general de fuerza;
- una sesión de aceleración;
- una sesión fuerza + aceleración;
- una sesión de potencia;
- una sesión de aprendizaje de aterrizaje;
- una sesión de desaceleración;
- una sesión básica de COD;
- una sesión de agilidad simple;
- sesiones realizables en campo;
- sesiones realizables en gimnasio;
- sesiones con poco material.

Además debe permitir crear:

- progresiones;
- regresiones;
- sustituciones.

Si un conjunto de ejercicios no permite estas cosas:

> todavía no representa suficientemente FORJA.

---

# 4. Criterios de inclusión

Una tarea podrá entrar en la biblioteca inicial cuando cumpla una o varias funciones necesarias y supere los siguientes criterios.

### 4.1. Utilidad

Debe resolver un problema real de entrenamiento.

### 4.2. Claridad

Debe ser relativamente fácil entender:

- qué pretende;
- cómo se ejecuta;
- qué observamos.

### 4.3. Capacidad de progresión

Debe permitir modificar demanda o relacionarse con otras tareas.

### 4.4. Aplicabilidad juvenil

Debe poder utilizarse razonablemente en jóvenes cuando la variante y dosis sean apropiadas.

### 4.5. Accesibilidad

Preferiremos tareas con:

- poco material;
- material habitual;
- variantes accesibles.

### 4.6. Transferibilidad de contexto

Cuando sea posible, una tarea debería poder utilizarse en:

- campo;
- gimnasio;
- casa;

o disponer de sustituciones razonables.

### 4.7. Valor pedagógico

La tarea debe permitir observar y enseñar algo útil.

### 4.8. No redundancia

No añadiremos varias tareas que representan prácticamente el mismo problema sin una razón.

---

# 5. Criterios de exclusión inicial

Una tarea podrá quedar fuera de esta primera biblioteca cuando:

- sea muy específica;
- requiera equipamiento poco habitual;
- duplique otra tarea;
- requiera competencia elevada sin aportar una rama necesaria;
- no tenga todavía una función clara;
- su clasificación genere dudas relevantes;
- no podamos definir suficientemente su progresión o regresión.

Quedar fuera no significa:

> ejercicio incorrecto.

Significa:

> **no necesario todavía.**

---

# 6. Número inicial

FORJA establecerá inicialmente:

> **25 ejercicios base.**

Este número no constituye un estándar futuro.

La selección comenzó conceptualmente con 24 tareas.

Durante la revisión se decidió separar:

- remo con banda;
- remo en suspensión;

porque, aunque comparten patrón principal, presentan diferencias suficientemente útiles en:

- material;
- forma de aplicar resistencia;
- posición corporal;
- regulación de demanda;
- posibilidades de progresión.

FORJA prefiere aceptar una biblioteca de 25 ejercicios antes que fusionar artificialmente tareas únicamente para cumplir una cifra predeterminada.

La biblioteca podrá ampliarse o revisarse después de ser utilizada.

---

# 7. Cobertura de patrones

Los 25 ejercicios deben cubrir las once familias de [PAT-001](../04-movement-patterns/movement-pattern-model.md):

1. dominante de rodilla;
2. bisagra / dominante de cadera;
3. unilateral / zancada;
4. empuje;
5. tracción;
6. tronco / estabilización / transporte;
7. salto;
8. aterrizaje;
9. aceleración y sprint;
10. desaceleración;
11. cambio de dirección y agilidad.

La distribución no será uniforme.

No necesitamos:

> dos ejercicios de cada patrón.

Algunas familias necesitan más variedad inicial que otras.

---

# 8. Dominante de rodilla

### EX-001 — Sentadilla asistida

Función inicial:

- aprendizaje;
- control;
- regresión útil.

Razón de inclusión:

permite introducir el patrón con baja demanda y utilizar asistencia como herramienta, no como etiqueta de inferioridad.

---

### EX-002 — Sentadilla goblet

Función inicial:

- fuerza;
- competencia;
- progresión de carga.

Razón de inclusión:

ejercicio accesible, fácil de cargar y con múltiples posibilidades de prescripción.

---

# 9. Bisagra / dominante de cadera

### EX-003 — Bisagra de cadera

Función inicial:

- aprendizaje del patrón.

Razón de inclusión:

permite separar aprendizaje técnico de carga externa.

---

### EX-004 — Peso muerto rumano con mancuernas

Función inicial:

- fuerza;
- progresión de bisagra.

Razón de inclusión:

permite aplicar carga de forma sencilla sin necesitar inicialmente una barra.

---

# 10. Unilateral / zancada

### EX-005 — Split squat

Función inicial:

- fuerza unilateral;
- control.

Razón de inclusión:

permite trabajar apoyo asimétrico sin necesidad de desplazamiento.

---

### EX-006 — Reverse lunge

Función inicial:

- fuerza unilateral;
- competencia dinámica.

Razón de inclusión:

añade desplazamiento y control respecto al split squat.

---

### EX-007 — Step-up

Función inicial:

- fuerza unilateral;
- producción de fuerza desde apoyo elevado.

Razón de inclusión:

ofrece una rama diferente dentro del trabajo unilateral.

---

# 11. Empuje

### EX-008 — Flexión

Función inicial:

- fuerza de empuje;
- control corporal.

Razón de inclusión:

no necesita material y dispone de múltiples regresiones y progresiones.

---

### EX-009 — Press unilateral con mancuerna

Función inicial:

- empuje;
- fuerza;
- control del tronco.

Razón de inclusión:

permite carga externa sencilla y trabajo unilateral del tren superior.

La posición concreta y variantes se definirán en su futura ficha.

---

# 12. Tracción

### EX-010 — Remo con banda

Función inicial:

- tracción;
- aprendizaje;
- fuerza.

Razón de inclusión:

permite trabajar el patrón de tracción con material ligero y portátil.

La resistencia puede modificarse mediante:

- características de la banda;
- longitud efectiva;
- posición;
- rango;

según la tarea.

---

### EX-011 — Remo en suspensión

Función inicial:

- tracción;
- fuerza;
- control corporal.

Razón de inclusión:

utiliza el peso corporal y la posición del deportista para modificar la demanda.

Aunque comparte patrón con el remo con banda, se mantiene como ficha independiente porque cambian suficientemente:

- el material;
- la forma de aplicar resistencia;
- la posición corporal;
- la regulación de la demanda;
- algunas progresiones y regresiones.

---

### EX-012 — Remo unilateral con mancuerna

Función inicial:

- fuerza de tracción;
- control.

Razón de inclusión:

permite progresión de carga externa con material habitual.

---

# 13. Tronco / estabilización / transporte

### EX-013 — Plancha frontal

Función inicial:

- control anti-extensión.

Razón de inclusión:

tarea sencilla para introducir control del tronco.

---

### EX-014 — Pallof press

Función inicial:

- anti-rotación.

Razón de inclusión:

representa un problema diferente al de la plancha.

---

### EX-015 — Suitcase carry

Función inicial:

- transporte;
- control anti-inclinación;
- locomoción con carga.

Razón de inclusión:

integra tronco, postura y desplazamiento.

---

# 14. Salto

### EX-016 — Salto vertical + estabilización

Función inicial:

- producción vertical;
- aprendizaje de aterrizaje.

Patrón principal:

- salto.

Secundario:

- aterrizaje.

Razón de inclusión:

permite introducir intención explosiva manteniendo control de recepción.

---

### EX-017 — Salto horizontal + estabilización

Función inicial:

- producción horizontal;
- potencia;
- aterrizaje.

Razón de inclusión:

introduce una dirección distinta y conecta con aceleración.

---

### EX-018 — Pogo bilateral

Función inicial:

- reactividad básica;
- contactos rápidos.

Razón de inclusión:

introduce continuidad y reutilización rápida de fuerza sin necesitar gran complejidad.

---

# 15. Aterrizaje

### EX-019 — Caída baja + estabilización

Función inicial:

- absorción;
- control de aterrizaje.

Razón de inclusión:

permite que aterrizar sea el objetivo principal sin necesidad de producir previamente un gran salto.

No utilizar alturas elevadas en la definición base.

---

# 16. Aceleración y sprint

### EX-020 — Aceleración corta

Función inicial:

- aceleración.

Variante principal:

- aproximadamente 5–10 m según objetivo.

Razón de inclusión:

evita crear fichas prácticamente duplicadas para sprint 5 m y 10 m.

La distancia será una variable de prescripción o variante.

---

### EX-021 — Sprint de mayor exposición

Función inicial:

- desarrollar fases posteriores de aceleración;
- permitir exposición a velocidades superiores a las alcanzadas en una aceleración muy corta.

La distancia concreta dependerá del objetivo, competencia y contexto.

Razón de inclusión:

la biblioteca necesita una tarea distinta de la aceleración muy corta sin convertir cada distancia en ejercicio independiente.

IMPORTANTE:

No definir "mayor exposición" mediante una distancia universal en LIB-001.

La futura ficha deberá precisar cómo interpretar y prescribir esta tarea.

---

# 17. Desaceleración

### EX-022 — Aceleración + parada en zona

Función inicial:

- aprender a frenar.

Razón de inclusión:

es una tarea sencilla donde desaceleración constituye claramente el objetivo principal.

---

# 18. Cambio de dirección

### EX-023 — COD preplanificado de ángulo pequeño/moderado

Función inicial:

- aprender a redirigir trayectoria manteniendo parte de la velocidad.

Ejemplo contextual:

- aproximadamente 45°.

El ángulo exacto será atributo o variable.

Razón de inclusión:

permite introducir COD con menor necesidad de frenado que cambios grandes.

---

### EX-024 — COD preplanificado de ángulo grande

Función inicial:

- desacelerar;
- reorganizar apoyos;
- reacelerar.

Ejemplo contextual:

- aproximadamente 90° o superior según tarea.

Razón de inclusión:

representa una demanda suficientemente diferente para justificar una ficha base separada.

---

# 19. Agilidad

### EX-025 — COD reactivo simple

Función inicial:

- percepción;
- decisión;
- cambio de dirección.

Ejemplo:

dos direcciones posibles determinadas mediante una señal tardía.

Razón de inclusión:

introduce incertidumbre sin convertir la tarea en un ejercicio deportivo excesivamente complejo.

---

# 20. Por qué no incluir sprint 5 m y sprint 10 m como fichas diferentes

La distancia modifica la tarea.

Pero no toda modificación necesita una nueva ficha.

En la biblioteca inicial utilizaremos:

> **Aceleración corta**

como ejercicio base.

La distancia podrá variar dentro de la prescripción.

Se creará una ficha nueva únicamente si el cambio modifica suficientemente:

- objetivo;
- fase de carrera;
- requisitos;
- ejecución;
- prescripción.

Esto aplica [EX-STD-001](exercise-card-standard.md).

---

# 21. Por qué incluir dos tipos de COD

A diferencia de pequeñas variaciones de distancia, el ángulo puede modificar profundamente:

- velocidad de entrada tolerable;
- desaceleración necesaria;
- estrategia;
- reaceleración.

Por ello la biblioteca inicial distingue:

- COD de ángulo pequeño/moderado;
- COD de ángulo grande.

No implica que 45° y 90° sean categorías absolutas universales.

Representan dos problemas suficientemente diferentes.

---

# 22. Por qué separar salto y aterrizaje

[PAT-001](../04-movement-patterns/movement-pattern-model.md), [SCI-006](../02-science/youth-power-and-plyometrics.md) y [SCI-007](../02-science/youth-change-of-direction-agility.md) establecieron que:

> producir fuerza y absorberla son problemas relacionados pero diferentes.

Por ello existen:

- saltos con aterrizaje como componente secundario;
- una tarea específica donde aterrizar es el objetivo principal.

Esto permitirá crear progresiones de recepción antes de aumentar reactividad cuando corresponda.

---

# 23. Por qué separar remo con banda y remo en suspensión

Ambas tareas comparten el patrón principal de tracción.

Pero la biblioteca inicial las considera ejercicios base diferentes porque cambia suficientemente la naturaleza de la tarea.

En el remo con banda:

- la resistencia procede principalmente de un elemento elástico;
- la resistencia cambia con la elongación;
- la demanda puede ajustarse modificando banda, distancia o tensión;
- el cuerpo puede permanecer relativamente estable respecto al entorno.

En el remo en suspensión:

- una parte relevante de la resistencia procede del peso corporal;
- la inclinación corporal modifica la demanda;
- existe una interacción diferente entre tracción y control corporal;
- las progresiones y regresiones pueden depender de la posición del cuerpo y los apoyos.

Por tanto:

> compartir patrón no obliga a compartir ficha.

Esta separación sirve además como ejemplo práctico del criterio de [EX-STD-001](exercise-card-standard.md) para decidir cuándo una variante merece identidad propia.

---

# 24. Por qué no incluir depth jump inicialmente

El depth jump:

- puede tener utilidad;
- puede formar parte de progresiones futuras.

Pero no es necesario para validar la primera biblioteca.

Requiere más:

- experiencia;
- competencia;
- control de carga.

Por tanto queda fuera inicialmente.

Su ausencia no significa rechazo metodológico.

---

# 25. Por qué no incluir sentadilla con barra inicialmente

La biblioteca inicial ya puede desarrollar dominante de rodilla mediante:

- sentadilla asistida;
- sentadilla goblet.

Una sentadilla con barra puede añadirse posteriormente cuando necesitemos:

- mayor carga;
- una rama específica de progresión.

No necesitamos introducirla únicamente porque sea habitual en entrenamiento de fuerza.

---

# 26. Por qué no incluir peso muerto convencional inicialmente

La bisagra queda representada mediante:

- aprendizaje de bisagra de cadera;
- peso muerto rumano con mancuernas.

Esto permite validar:

- patrón;
- carga;
- progresión;

sin añadir todavía variantes de mayor complejidad logística.

---

# 27. Por qué no incluir dominada inicialmente

La dominada es una tarea válida.

Pero requiere un nivel relativo de fuerza que puede limitar su utilización como tarea base para algunos jóvenes.

La tracción ya queda cubierta mediante:

- remo con banda;
- remo en suspensión;
- remo unilateral con mancuerna.

La dominada podrá añadirse como rama futura.

---

# 28. Por qué no incluir ejercicios olímpicos

No son necesarios para validar la primera biblioteca.

La potencia puede desarrollarse inicialmente mediante:

- saltos;
- sprint;
- otras tareas de velocidad.

Los levantamientos olímpicos pueden ser útiles en determinados contextos.

Pero su inclusión requiere justificar:

- competencia;
- aprendizaje;
- material;
- supervisión.

No son requisito para FORJA.

---

# 29. Por qué no incluir escalera de coordinación

Los fundamentos metodológicos y científicos de FORJA establecen que una escalera puede utilizarse para:

- ritmo;
- coordinación;
- preparación.

Pero no representa por sí misma:

- agilidad;
- COD;
- desaceleración.

La biblioteca inicial prioriza tareas con un objetivo más directamente identificable.

Puede añadirse posteriormente como tarea específica si existe una razón.

---

# 30. Por qué no incluir ejercicios llamados "preventivos"

Prevención no es un patrón.

La biblioteca inicial incluirá tareas por sus capacidades reales:

- fuerza;
- aterrizaje;
- control;
- tolerancia.

No crearemos una familia de ejercicios preventivos.

---

# 31. Por qué no incluir ejercicios de movilidad como familia

Movilidad no forma parte de las once familias iniciales.

Puede ser:

- capacidad;
- preparación;
- requisito.

La biblioteca de movimientos podrá ampliarse posteriormente con tareas de preparación cuando exista una necesidad.

Pero LIB-001 prioriza los ejercicios necesarios para construir sesiones principales.

---

# 32. Material necesario para la biblioteca completa

Para poder realizar prácticamente toda la biblioteca inicial bastaría con disponer de una combinación razonable de:

- espacio;
- conos o referencias;
- banda elástica;
- mancuerna o kettlebell;
- superficie estable;
- banco/cajón bajo;
- sistema de suspensión.

No todo ejercicio necesita todo el material.

La biblioteca debe seguir siendo utilizable con recursos limitados.

La ausencia de sistema de suspensión no impide construir una sesión FORJA.

Simplemente elimina temporalmente una opción concreta.

---

# 33. Biblioteca de campo

Con poco material en campo podrán utilizarse, entre otros:

- sentadilla asistida;
- split squat;
- reverse lunge;
- flexión;
- plancha;
- salto vertical;
- salto horizontal;
- pogos;
- aterrizaje;
- aceleración;
- sprint;
- desaceleración;
- COD;
- agilidad.

Con bandas u otro material portátil pueden añadirse tareas adicionales.

Por tanto:

> **FORJA puede construir sesiones completas sin gimnasio.**

---

# 34. Biblioteca de gimnasio

El gimnasio permitirá aumentar opciones de:

- carga;
- resistencia;
- tracción;
- empuje;
- transporte.

Pero la lógica seguirá siendo la misma.

No existirá:

> biblioteca seria de gimnasio

frente a

> biblioteca inferior de campo.

Son contextos diferentes.

---

# 35. Relaciones iniciales

LIB-001 no define todavía todas las redes.

Pero debe ser posible establecer relaciones básicas.

Ejemplo:

### Dominante de rodilla

Sentadilla asistida  
→ Sentadilla goblet.

### Bisagra

Bisagra de cadera  
→ Peso muerto rumano con mancuernas.

### Tracción

Remo con banda / remo en suspensión / remo unilateral con mancuerna

pueden constituir ramas diferentes según:

- material;
- objetivo;
- competencia;
- forma de aplicar resistencia.

No establecer una escalera universal entre las tres.

### COD

COD preplanificado  
→ COD reactivo simple.

### Aterrizaje / salto

Caída + estabilización  
↔ Salto + estabilización  
→ Pogo cuando el objetivo y competencia lo permitan.

Las flechas son ejemplos de relación.

No una progresión universal.

---

# 36. Sustituciones iniciales

La biblioteca debe permitir alternativas.

Ejemplo:

si no existe carga externa:

sentadilla goblet puede sustituirse temporalmente por una variante de sentadilla con otra forma de resistencia cuando conserve suficientemente el objetivo.

Si no existe sistema de suspensión:

puede seleccionarse una alternativa de tracción como remo con banda cuando resulte adecuada.

IMPORTANTE:

Sustitución no significa equivalencia perfecta.

El estándar de ficha definirá posteriormente las sustituciones concretas.

---

# 37. Cobertura de capacidades

La biblioteca inicial debe permitir entrenar al menos:

- competencia motriz;
- fuerza;
- potencia;
- aceleración;
- velocidad;
- aterrizaje;
- desaceleración;
- COD;
- agilidad;
- control.

No todas mediante ejercicios exclusivos.

Una misma tarea puede contribuir a varias capacidades.

---

# 38. Cobertura no significa equilibrio numérico

No necesitamos:

- mismo número de ejercicios de fuerza;
- mismo número de saltos;
- mismo número de COD.

Las necesidades de representación son distintas.

Por ejemplo:

el bloque de fuerza necesita más patrones estructurales.

El bloque de desaceleración puede comenzar con una sola tarea base muy bien definida.

---

# 39. Qué debe permitir una primera sesión de fuerza

Con esta biblioteca podemos seleccionar, por ejemplo:

- sentadilla goblet;
- peso muerto rumano;
- split squat;
- flexión;
- una variante de remo;
- suitcase carry.

No necesitamos utilizar todas.

Pero existe suficiente cobertura para construir una sesión coherente.

---

# 40. Qué debe permitir una primera sesión de aceleración

Podemos combinar:

- aceleración corta;
- salto horizontal;
- una tarea de fuerza;
- tronco;

según objetivo y contexto.

Esto aplica [MET-003](../03-methodology/session-construction.md).

---

# 41. Qué debe permitir una primera sesión de desaceleración

Podemos utilizar:

- aceleración + parada;
- caída + estabilización;
- split squat;
- COD preplanificado;

según competencia.

---

# 42. Qué debe permitir una primera sesión de agilidad

Podemos progresar conceptualmente desde:

- aceleración;
- desaceleración;
- COD preplanificado;
- COD reactivo simple.

La biblioteca contiene ya suficientes nodos para construir esa secuencia.

No constituye una progresión universal obligatoria.

---

# 43. Biblioteca inicial no significa programa inicial

Los 25 ejercicios no se utilizarán todos.

La biblioteca representa:

> **opciones disponibles.**

El programa seleccionará únicamente las necesarias.

Esto preserva:

> patrón ≠ ejercicio ≠ programa.

---

# 44. Una ficha por ejercicio base

Cada una de las 25 tareas tendrá posteriormente una ficha siguiendo [EX-STD-001](exercise-card-standard.md).

Las variantes menores:

- no generarán inicialmente fichas independientes;
- se registrarán dentro de la ficha correspondiente.

Esto reducirá duplicados.

---

# 45. Orden de creación de fichas

La biblioteca se desarrollará en tres lotes.

### Lote A — Fuerza y control

EX-001 a EX-015.

Incluye:

- dominante de rodilla;
- bisagra;
- unilateral;
- empuje;
- tracción;
- tronco.

### Lote B — Potencia y velocidad

EX-016 a EX-021.

Incluye:

- salto;
- aterrizaje;
- aceleración;
- sprint.

### Lote C — Desaceleración y multidireccional

EX-022 a EX-025.

Incluye:

- desaceleración;
- COD;
- agilidad.

Esto facilita revisión por bloques.

---

# 46. Revisión después de cada lote

No generaremos necesariamente las 25 fichas antes de revisar.

Después de cada lote comprobaremos:

- claridad;
- duplicados;
- calidad de relaciones;
- utilidad práctica;
- consistencia con [EX-STD-001](exercise-card-standard.md).

Si el estándar necesita ajustes:

> se ajustará antes de multiplicar el error.

---

# 47. Criterio para ampliar la biblioteca

Un nuevo ejercicio se añadirá cuando exista una necesidad como:

- falta una progresión;
- falta una regresión;
- falta una sustitución;
- un objetivo no puede abordarse bien;
- el material disponible exige otra opción;
- una variante ha adquirido suficiente identidad propia;
- un caso real descubre un hueco.

No porque queramos alcanzar:

> 50, 100 o 500 ejercicios.

---

# 48. Proyecto real como prueba de la biblioteca

La biblioteca deberá ponerse a prueba construyendo programas reales.

Eso permitirá detectar:

- huecos;
- redundancias;
- relaciones incorrectas;
- campos innecesarios.

FORJA no asumirá que la biblioteca es correcta simplemente porque está bien documentada.

Debe funcionar.

---

# 49. Biblioteca y futuro software

En una futura aplicación, esta selección permitirá funcionalidades como:

- filtrar por patrón;
- filtrar por capacidad;
- filtrar por material;
- seleccionar regresión;
- seleccionar progresión;
- buscar sustitución;
- construir sesiones.

Pero LIB-001 no implementa esa tecnología.

Define el contenido inicial sobre el que podrá construirse.

---

# 50. Identificadores provisionales

Los códigos:

`EX-001` a `EX-025`

se utilizarán inicialmente para ordenar el trabajo documental.

No deben interpretarse todavía como el identificador técnico definitivo de la futura aplicación.

[EX-STD-001](exercise-card-standard.md) establece que el identificador técnico deberá ser estable.

Ese diseño se decidirá posteriormente.

---

# 51. Nombres provisionales

Los nombres de ejercicios podrán refinarse durante la creación de fichas.

LIB-001 no obliga a conservar artificialmente una selección o denominación si el desarrollo de las fichas demuestra que debe modificarse.

Una tarea puede:

- cambiar de nombre;
- dividirse;
- integrarse como variante;
- ser sustituida;

si existe justificación metodológica.

Cualquier cambio deberá conservar trazabilidad.

---

# 52. La biblioteca es versionable

Esta primera colección representa:

> **Biblioteca inicial v0.1 conceptual.**

No una versión definitiva.

Las incorporaciones y modificaciones deberán quedar documentadas.

Esto permite mejorar sin perder trazabilidad.

---

# 53. Qué no evaluaremos todavía

LIB-001 no establecerá todavía:

- rankings de mejores ejercicios;
- niveles absolutos;
- puntuación por ejercicio;
- transferencia cuantificada;
- dificultad numérica;
- edad mínima universal;
- edad máxima universal;
- frecuencia universal;
- dosis universal.

Todo eso sería falsa precisión en esta fase.

# 54. Errores frecuentes

### Añadir muchos ejercicios desde el principio

**Error:** confundir biblioteca grande con biblioteca útil.

**FORJA:** empezar pequeña y ampliar por necesidad.

### Crear fichas para cada mínima variante

**Error:** generar duplicados.

**FORJA:** utilizar ejercicio base + variantes.

### Añadir ejercicios porque parecen avanzados

**Error:** espectacularidad como criterio.

**FORJA:** utilidad como criterio.

### Cubrir patrones por aritmética

**Error:** exigir el mismo número de ejercicios por familia.

**FORJA:** cubrir necesidades, no cuotas.

### Mantener una cifra por obligación

**Error:** fusionar o eliminar ejercicios para cumplir un número predeterminado.

**FORJA:** el contenido determina el tamaño de la biblioteca.

### Confundir biblioteca con programa

**Error:** querer utilizar todo lo disponible.

**FORJA:** seleccionar únicamente lo necesario.

### Considerar la selección definitiva

**Error:** impedir ajustes después de usarla.

**FORJA:** aprender de la aplicación.

---

# 55. Decisiones FORJA

### F-LIB-001 — La biblioteca inicial será deliberadamente pequeña

Comenzará con 25 ejercicios base.

El número no constituye un objetivo permanente.

### F-LIB-002 — Cada ejercicio debe justificar su presencia

Popularidad o espectacularidad no son criterios suficientes.

### F-LIB-003 — La biblioteca debe cubrir las once familias PAT

Sin necesidad de distribución uniforme.

### F-LIB-004 — Se priorizarán tareas accesibles

Poco material y alta utilidad cuando sea posible.

### F-LIB-005 — La biblioteca debe permitir construir sesiones reales

No será únicamente una taxonomía.

### F-LIB-006 — Las variantes menores permanecerán dentro de fichas base

Se evitarán duplicados innecesarios.

### F-LIB-007 — La distancia no crea automáticamente un ejercicio nuevo

Aceleración 5 m y 10 m podrán compartir ficha base cuando el objetivo sea suficientemente equivalente.

### F-LIB-008 — Demandas suficientemente diferentes pueden justificar fichas distintas

Como ocurre inicialmente con COD de ángulo pequeño/moderado y grande.

### F-LIB-009 — Compartir patrón no obliga a compartir ficha

Remo con banda y remo en suspensión se separan porque la naturaleza de la resistencia, regulación de demanda y progresión justifican identidades diferentes.

### F-LIB-010 — Los ejercicios avanzados no son necesarios para validar FORJA

Depth jumps, levantamientos olímpicos y otras tareas podrán añadirse posteriormente.

### F-LIB-011 — Campo y gimnasio son contextos válidos

La biblioteca debe funcionar con diferentes recursos.

### F-LIB-012 — La biblioteca se construirá por lotes

Primero fuerza/control, después potencia/velocidad y finalmente multidireccional.

### F-LIB-013 — Cada lote será revisado antes de escalar

No se multiplicarán errores de estructura.

### F-LIB-014 — La biblioteca crecerá por necesidad

No por objetivos numéricos.

### F-LIB-015 — Un caso real podrá modificar la biblioteca

La aplicación forma parte de la validación.

### F-LIB-016 — EX-001 a EX-025 son identificadores documentales provisionales

No el estándar técnico definitivo.

### F-LIB-017 — LIB-001 selecciona ejercicios; [EX-STD-001](exercise-card-standard.md) define sus fichas

Las responsabilidades se mantienen separadas.

### F-LIB-018 — El tamaño de la biblioteca es consecuencia de las necesidades

No se fusionarán tareas artificialmente para cumplir una cifra predeterminada.

# 57. Qué significa esto para el entrenador

La biblioteca inicial no responde:

> **¿qué ejercicios debo hacer?**

Responde:

> **¿qué opciones suficientemente definidas tiene FORJA para construir una solución?**

Después:

- el perfil selecciona necesidades;
- la metodología establece prioridades;
- la sesión organiza;
- la prescripción dosifica;
- la semana distribuye;
- la biblioteca aporta tareas.

# Ideas clave finales

Si solo recuerdas ocho ideas:

1. **La primera biblioteca FORJA tendrá 25 ejercicios base.**
2. **Cada ejercicio entra porque aporta una función necesaria.**
3. **Las once familias quedan representadas sin cuotas artificiales.**
4. **Las variantes menores no crearán fichas innecesarias.**
5. **La biblioteca debe permitir construir sesiones reales con y sin gimnasio.**
6. **Los ejercicios avanzados se añadirán cuando exista una necesidad.**
7. **Las fichas se crearán y revisarán por lotes.**
8. **La biblioteca crecerá a partir de uso real, no por acumular ejercicios.**
