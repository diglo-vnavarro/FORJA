# Estándar visual de ejercicios FORJA

## Propósito

Definir cómo representará FORJA visualmente los ejercicios de su biblioteca para mantener:

- claridad;
- consistencia;
- utilidad técnica;
- identidad propia;
- escalabilidad.

VIS-001 no pretende convertir cada ejercicio en una ilustración artística.

La imagen debe responder:

> **¿qué necesito ver para entender mejor esta tarea?**

---

# 1. Principio fundamental

La ilustración complementa la ficha.

No la sustituye.

Una imagen puede ayudar a entender:

- posición;
- dirección;
- secuencia;
- espacio;
- organización.

Pero no debe ser la única fuente para comprender:

- objetivo;
- dosis;
- seguridad;
- criterios de competencia.

Una única ficha metodológica puede producir diferentes representaciones visuales según el contexto de uso.

La ficha EX continúa siendo la única fuente metodológica de verdad.

No existirán tres versiones independientes del conocimiento.

---

# Arquitectura visual FORJA

FORJA utilizará tres niveles visuales complementarios.

Los términos Nivel 1, Nivel 2 y Nivel 3 describen exclusivamente tipos de recurso visual.

No representan dificultad del ejercicio ni del deportista.

## Nivel 1 — Ilustración maestra

### Función

Representar visualmente el ejercicio base de forma limpia y técnicamente comprensible.

### Características

- estilo editorial y técnico;
- apariencia profesional;
- deportista juvenil genérico;
- anatomía plausible;
- ropa neutra;
- ausencia de marcas;
- fondo limpio;
- ausencia de decoración innecesaria;
- pocas fases;
- texto mínimo;
- perspectiva elegida por claridad;
- material coherente con la ficha;
- ausencia de criterios técnicos no presentes en la ficha.

### Uso

- ficha maestra;
- documentación;
- web;
- base para futuras composiciones visuales;
- referencia para derivaciones gráficas.

El estilo visual principal será una ilustración editorial deportiva, técnica, limpia y contemporánea, semi-realista o estilizada con anatomía plausible.

No necesita ser fotográfica.

No utilizará estética de cartoon infantil, culturismo, representación clínica ni hiperrealismo innecesario.

El deportista debe transmitir:

> joven deportista.

No:

> adulto fitness profesional.

El Prototipo A de [EX-002 — Sentadilla goblet](library/ex-002-goblet-squat.md) ha validado conceptualmente este lenguaje mediante:

- aspecto profesional;
- joven deportista;
- fondo limpio;
- dos fases;
- lectura clara;
- estética editorial deportiva.

La representación aprobada conceptualmente contiene:

- posición inicial;
- posición inferior.

La ilustración maestra no intenta mostrar toda la ficha.

Su función es enseñar visualmente la tarea.

## Nivel 2 — Infografía web

### Función

Permitir comprender rápidamente el ejercicio dentro de la web o aplicación FORJA.

Debe reutilizar el lenguaje visual del Nivel 1.

No creará un personaje ni un estilo completamente diferente.

Puede combinar, según utilidad y legibilidad:

- ilustración maestra;
- nombre;
- identificador;
- objetivo;
- patrón principal;
- capacidades;
- material;
- secuencia;
- consignas seleccionadas;
- indicadores de competencia;
- errores relevantes;
- regresión o progresión;
- variables de prescripción.

No todos estos elementos deben mostrarse simultáneamente.

La ficha EX continúa siendo la fuente completa.

La infografía web no debe:

- inventar niveles;
- añadir clasificaciones absolutas como básico, intermedio o avanzado;
- inventar técnica;
- crear nuevas reglas;
- convertir ejemplos en prescripciones universales;
- introducir información no aprobada en la ficha.

Su objetivo es permitir que un entrenador comprenda la tarea y sus claves principales en pocos segundos sin reemplazar la ficha completa.

La infografía web se compone:

> **VISUAL + INFORMACIÓN DE LA FICHA**

No se genera como un bloque independiente de conocimiento.

La maquetación futura podrá mostrar módulos como:

- identidad;
- objetivo;
- movimiento;
- claves;
- competencia;
- prescripción;
- relaciones.

VIS-001 no fija todavía una plantilla de interfaz definitiva.

La primera infografía web definitiva será [EX-002 — Sentadilla goblet](library/ex-002-goblet-squat.md).

Utilizará:

- ilustración maestra de Nivel 1;
- únicamente contenido aprobado de EX-002;
- una arquitectura informativa coherente con VIS-001.

No se crea en esta revisión.

## Nivel 3 — Ficha rápida de sesión

### Función

Ofrecer una representación extremadamente compacta del ejercicio cuando forma parte de una sesión.

Puede utilizar un lenguaje vectorial simplificado derivado del Prototipo B.

### Características

- dibujo más simple;
- máxima legibilidad a tamaño pequeño;
- poco detalle;
- mismas fases esenciales del ejercicio;
- mismo material;
- perspectiva coherente cuando sea posible;
- mismo lenguaje general de identidad FORJA.

Debe ser una simplificación del Nivel 1, no una reinterpretación técnica diferente.

Priorizará:

- silueta;
- posición;
- secuencia;
- carga;
- lectura rápida.

Podrá reducir:

- detalle facial;
- texturas;
- sombras;
- anatomía secundaria.

No reducirá la claridad técnica.

Según la sesión, puede contener:

- identificador o nombre;
- miniatura del ejercicio;
- objetivo inmediato;
- entre dos y cuatro consignas;
- dosis concreta prescrita para esa sesión;
- recuperación;
- criterio de parada relevante;
- regresión o progresión inmediata cuando aporte valor.

La dosis procede de la sesión y de la programación.

No pertenece permanentemente a la imagen ni a la ficha base EX.

El Prototipo B ha validado únicamente el potencial del lenguaje vectorial y simplificado para el Nivel 3.

No se considera aprobado su contenido textual ni las etiquetas generadas durante la prueba.

La primera prueba posterior de Nivel 3 utilizará EX-002 dentro de una sesión real o simulada, con miniatura simplificada, contenido contextual y texto mínimo.

No se crea en esta revisión.

## Una fuente de verdad

La arquitectura conceptual será:

> **FICHA EX**
>
> ↓
>
> **CONOCIMIENTO APROBADO**
>
> ↓
>
> **REPRESENTACIÓN VISUAL**
>
> ├── Nivel 1 — Ilustración maestra
>
> ├── Nivel 2 — Infografía web
>
> └── Nivel 3 — Ficha rápida de sesión

No se mantendrán manualmente tres versiones diferentes de:

- consignas;
- objetivos;
- patrones;
- criterios;
- progresiones.

Cada representación selecciona información de la misma ficha.

## Coherencia entre Nivel 1 y Nivel 3

Cuando sea posible, ambos niveles conservarán:

- el mismo personaje conceptual;
- la misma ropa;
- los mismos colores generales;
- el mismo material;
- la misma perspectiva;
- las mismas fases principales.

El Nivel 3 simplifica.

No cambia la ejecución.

## Contenido estable y contenido contextual

### Contenido estable del ejercicio

- nombre;
- patrones;
- objetivos posibles;
- ejecución;
- indicadores;
- material;
- relaciones.

### Contenido contextual de sesión

- series;
- repeticiones;
- carga;
- distancia;
- descanso;
- RPE objetivo;
- variante elegida;
- criterio de parada específico del día.

La ficha rápida de sesión puede mostrar ambos, pero debe diferenciarlos conceptualmente.

## Cantidad de texto

- Nivel 1: texto mínimo o inexistente.
- Nivel 2: texto suficiente para una comprensión rápida.
- Nivel 3: texto extremadamente reducido.

No se colocarán párrafos largos dentro de recursos gráficos.

## Representación de errores

No se generará de forma predeterminada una galería de correcto frente a incorrecto.

Si un error merece representación visual, deberá derivarse de la sección «Errores relevantes» de la ficha EX.

No se inventará visualmente.

## Los niveles visuales no son dificultad

Las representaciones visuales no mostrarán básico, intermedio o avanzado como clasificación absoluta del ejercicio.

Tampoco utilizarán Nivel 1, Nivel 2 o Nivel 3 para expresar dificultad.

En VIS-001 estos términos describen únicamente formatos de representación.

---

# 2. Estilo visual FORJA

FORJA utilizará ilustraciones propias con un lenguaje gráfico consistente.

Características generales:

- deportista juvenil genérico;
- apariencia no identificable;
- ropa deportiva neutra;
- sin marcas;
- fondo limpio;
- prioridad a postura y movimiento;
- ausencia de elementos decorativos innecesarios.

La ilustración debe sentirse:

> técnica, limpia y contemporánea.

No infantil.

No clínica.

No hiperrealista innecesariamente.

---

# 3. El deportista visual

Se representará un deportista juvenil genérico.

No se utilizará la imagen de un joven real como identidad estándar.

El objetivo es:

- neutralidad;
- reutilización;
- privacidad;
- coherencia.

Podrán existir diferentes fenotipos y sexos a lo largo de la biblioteca.

Pero el estilo gráfico deberá mantenerse.

---

# 4. Edad visual

El personaje debe parecer claramente joven/adolescente cuando corresponda a FORJA.

No debe parecer:

- niño muy pequeño;
- culturista adulto;
- atleta profesional adulto.

La ilustración debe transmitir:

> joven deportista.

---

# 5. Indumentaria

Ropa sencilla:

- camiseta;
- pantalón deportivo;
- zapatillas apropiadas.

Sin:

- marcas visibles;
- clubes;
- selecciones;
- patrocinadores;
- camisetas identificables.

---

# 6. Fondo

Preferentemente:

- fondo blanco o muy limpio;
- suelo indicado cuando sea necesario;
- elementos espaciales mínimos.

No utilizar fondos fotográficos complejos.

Esto facilita:

- lectura;
- impresión;
- web;
- adaptación futura.

---

# 7. Número de imágenes por ejercicio

No existe un número obligatorio.

Como referencia:

## Ejercicio estático/simple

1–2 posiciones.

## Movimiento de fuerza

2–3 fases.

## Sprint/COD

Puede necesitar:

- diagrama espacial;
- secuencia corporal.

## Agilidad

Puede requerir:

- diagrama cenital;
- estímulo visual.

La cantidad depende de lo que ayude a comprender.

---

# 8. Posición inicial

Cuando sea relevante deberá quedar claramente identificada.

No es necesario escribir:

> posición inicial

sobre la imagen si el contexto visual ya lo permite.

Pero la secuencia debe ser inequívoca.

---

# 9. Fase principal

Representar la posición o fase que mejor explica el problema motor.

Ejemplo:

Goblet squat:

- inicio;
- posición inferior.

El regreso no necesita necesariamente una tercera imagen si resulta evidente.

---

# 10. Movimiento mediante flechas

Las flechas podrán utilizarse para representar:

- dirección del cuerpo;
- desplazamiento;
- trayectoria;
- sentido de carrera.

Deben ser:

- sencillas;
- claras;
- pocas.

No llenar la imagen de vectores biomecánicos.

---

# 11. Flechas no biomecánicas exactas

Una flecha visual representa:

> dirección práctica.

No una medición científica exacta de fuerza o velocidad.

No utilizar flechas que puedan interpretarse como:

- vectores cuantificados;
- fuerzas exactas;
- ángulos medidos;

salvo que realmente se trate de un diagrama específico.

---

# 12. Diagramas espaciales

Para tareas como:

- sprint;
- desaceleración;
- COD;
- agilidad;

FORJA podrá utilizar diagramas cenitales.

Estos podrán mostrar:

- salida;
- conos;
- dirección;
- zona de frenada;
- posibles alternativas;
- estímulo.

---

# 13. Distancias

Cuando una distancia sea parte esencial del ejercicio podrá indicarse.

Ejemplo:

`10 m`

Pero cuando sea una variable de prescripción:

la ilustración no debe convertir una distancia contextual en universal.

Ejemplo:

EX-020 Aceleración corta puede mostrar:

> 5–10 m

o no mostrar cifra y remitir a la ficha.

---

# 14. Ángulos

Los diagramas de COD podrán mostrar ejemplos como:

- 45°;
- 90°.

Pero deben quedar claramente interpretados como ejemplos cuando la ficha no los define como límites universales.

---

# 15. Color

La identidad cromática se definirá en el diseño general de FORJA.

VIS-001 no necesita fijar todavía códigos de color definitivos.

Principio:

- pocos colores;
- contraste suficiente;
- prioridad a lectura;
- consistencia.

No utilizar color únicamente por decoración.

---

# 16. Texto dentro de imágenes

Minimizarlo.

Puede utilizarse para:

- distancia;
- dirección;
- inicio;
- señal;
- zona.

La explicación técnica debe permanecer en la ficha.

Esto facilita:

- traducción;
- reutilización;
- accesibilidad.

---

# 17. Errores técnicos

FORJA no generará por defecto una segunda galería completa:

> correcto / incorrecto.

Cuando un error sea especialmente útil visualmente podrá representarse posteriormente.

Pero primero priorizaremos:

> cómo realizar la tarea.

---

# 18. Anatomía

No será necesario representar músculos activados en las ilustraciones principales.

La biblioteca organiza:

- patrones;
- capacidades;
- tareas.

No anatomía muscular como sistema principal.

---

# 19. Perspectiva

La perspectiva se elegirá según qué permita comprender mejor el ejercicio.

Puede ser:

- frontal;
- lateral;
- tres cuartos;
- cenital.

No utilizaremos una perspectiva única si perjudica comprensión.

---

# 20. Consistencia entre fichas

Ejercicios relacionados deberían usar perspectivas compatibles cuando ayude a comparar.

Ejemplo:

- sentadilla asistida;
- sentadilla goblet;

pueden compartir perspectiva lateral/tres cuartos.

Esto facilita observar diferencias.

---

# 21. Fuerza

Para ejercicios de fuerza, preferiremos representar:

- posición inicial;
- posición de mayor interés;
- colocación de carga.

No necesitamos mostrar cada centímetro del movimiento.

---

# 22. Saltos

Puede ser útil mostrar:

- posición inicial;
- despegue/acción;
- aterrizaje.

Cuando la recepción sea secundaria, dos fases pueden ser suficientes.

---

# 23. Aterrizajes

Cuando el objetivo sea aterrizar:

la recepción debe tener prioridad visual.

Puede ser más importante mostrar:

- contacto;
- estabilización;

que el movimiento previo.

---

# 24. Sprint

Las ilustraciones de sprint no intentarán enseñar una postura biomecánica universal perfecta.

Mostrarán:

- dirección;
- intención;
- organización espacial.

La técnica se explicará en la ficha cuando corresponda.

---

# 25. COD

Los diagramas deben priorizar:

- trayectoria;
- punto de cambio;
- salida;
- dirección posterior.

No sobrecargar con detalles anatómicos.

---

# 26. Agilidad

Cuando exista reacción deben representarse:

- opciones posibles;
- estímulo;
- momento de decisión;

cuando resulte necesario para comprender la tarea.

---

# 27. Material

El material representado debe coincidir con la ficha.

No mostrar:

- barra si la ficha utiliza mancuernas;
- suspensión si la ficha es remo con banda.

La imagen no debe crear ambigüedad.

---

# 28. Seguridad visual

No representar posiciones o contextos obviamente inseguros.

Ejemplo:

- cajón inestable;
- obstáculos demasiado próximos;
- sprint hacia pared;
- soporte débil.

---

# 29. Variantes

Una ficha no necesita ilustrar todas sus variantes.

La imagen principal representa:

> ejercicio base.

Las variantes pueden recibir ilustraciones futuras si aportan valor.

---

# 30. Nombres de archivos

El naming futuro debe ser predecible.

Propuesta conceptual:

`ex-002-goblet-squat-01.webp`

`ex-002-goblet-squat-02.webp`

No constituye todavía una decisión técnica definitiva.

---

# 31. Formatos

Para web se favorecerán formatos eficientes.

Conceptualmente:

- WebP para ilustraciones;
- SVG para diagramas cuando sea apropiado;
- PNG cuando exista necesidad concreta.

No establecer todavía pipeline técnico definitivo.

---

# 32. Resolución

Las imágenes deberán ser suficientemente grandes para:

- web;
- móvil;
- impresión documental razonable.

No necesitamos resoluciones enormes sin uso.

---

# 33. Accesibilidad

Cada imagen futura deberá disponer de:

- texto alternativo;
- descripción breve;

en la implementación digital.

El contenido importante nunca dependerá exclusivamente del color.

---

# 34. Derechos y propiedad

FORJA utilizará:

- imágenes propias;
- ilustraciones generadas específicamente;
- recursos con derechos adecuados.

No se copiarán fotografías de:

- Google;
- Instagram;
- libros;
- webs deportivas;

como contenido permanente de la biblioteca.

---

# 35. Consistencia generativa

Si las ilustraciones se generan mediante IA, se mantendrá una referencia visual estable para:

- personaje;
- estilo;
- proporciones;
- ropa;
- fondo;
- acabado.

No generar cada ficha con un estilo diferente.

---

# 36. Revisión humana

Toda ilustración debe revisarse.

Especialmente:

- manos;
- pies;
- carga;
- apoyos;
- dirección;
- número de extremidades;
- posición del material;
- coherencia con la ficha.

La imagen generada no se aceptará automáticamente.

---

# 37. La imagen no decide técnica

Si existe conflicto entre:

- imagen;
- ficha aprobada;

la ficha metodológica tiene prioridad.

La ilustración debe corregirse.

No al contrario.

---

# 38. Prototipo inicial

Antes de producir imágenes de toda la biblioteca se generará un prototipo.

Recomendación:

> [EX-002 — Sentadilla goblet](library/ex-002-goblet-squat.md).

Crear inicialmente:

- posición inicial;
- posición inferior.

Se revisará:

- estilo;
- claridad;
- personaje;
- ropa;
- perspectiva;
- utilidad.

Solo después se escalará.

---

# 39. Segundo prototipo

Después de validar una tarea de fuerza, conviene validar una espacial.

Recomendación:

> [EX-022 — Aceleración + parada en zona](initial-exercise-library.md).

Esto permitirá probar:

- diagrama cenital;
- conos;
- distancia;
- zona;
- flechas.

Así validaremos los dos principales sistemas visuales.

---

# 40. Decisiones FORJA

### F-VIS-001 — La imagen complementa

No sustituye la ficha.

### F-VIS-002 — FORJA utilizará un estilo visual propio

No una mezcla de imágenes externas.

### F-VIS-003 — El deportista será genérico

No representará una identidad real.

### F-VIS-004 — La ropa será neutra

Sin marcas ni clubes.

### F-VIS-005 — El fondo será limpio

El movimiento tendrá prioridad.

### F-VIS-006 — El número de fases depende de la tarea

No existe una cifra universal.

### F-VIS-007 — Las flechas serán funcionales

No decorativas ni falsamente biomecánicas.

### F-VIS-008 — Los diagramas espaciales tendrán entidad propia

Especialmente en sprint, COD y agilidad.

### F-VIS-009 — Distancias y ángulos contextuales no se convertirán visualmente en reglas universales

La imagen respetará la metodología.

### F-VIS-010 — El texto dentro de imágenes será mínimo

La ficha contiene la explicación.

### F-VIS-011 — Las perspectivas se elegirán por claridad

No por uniformidad absoluta.

### F-VIS-012 — Material e ilustración deben coincidir

No se aceptarán representaciones ambiguas.

### F-VIS-013 — Las imágenes principales mostrarán el ejercicio base

No todas las variantes.

### F-VIS-014 — FORJA utilizará recursos visuales propios o con derechos adecuados

No copiará imágenes externas arbitrariamente.

### F-VIS-015 — Las imágenes generadas requieren revisión humana

No se aceptan automáticamente.

### F-VIS-016 — La ficha tiene prioridad sobre la imagen

Cualquier inconsistencia se corrige visualmente.

### F-VIS-017 — Se validará un prototipo antes de escalar

Primero fuerza y después tarea espacial.

### F-VIS-018 — La accesibilidad forma parte del estándar

Las imágenes futuras tendrán descripción alternativa.

### F-VIS-019 — FORJA utilizará tres niveles visuales

Ilustración maestra, infografía web y ficha rápida de sesión.

### F-VIS-020 — La ficha EX es la fuente metodológica de verdad

Los recursos visuales derivan de ella.

### F-VIS-021 — Nivel 1 utiliza el lenguaje editorial técnico aprobado

Será la representación visual maestra del ejercicio.

### F-VIS-022 — Nivel 2 reutiliza el lenguaje del Nivel 1

La infografía añade información, no una nueva interpretación técnica.

### F-VIS-023 — Nivel 3 prioriza legibilidad compacta

Utilizará una simplificación gráfica coherente con el ejercicio maestro.

### F-VIS-024 — La dosis de sesión es contextual

No se almacenará como propiedad fija del recurso visual del ejercicio.

### F-VIS-025 — Las tres representaciones no duplican conocimiento

Seleccionan información de una misma fuente.

### F-VIS-026 — Los prototipos visuales no validan automáticamente su texto

Solo se consideran aprobadas las decisiones explícitamente incorporadas al estándar.

### F-VIS-027 — Los niveles visuales no representan dificultad

Nivel 1, 2 y 3 describen únicamente formatos de representación.

### F-VIS-028 — La primera infografía web definitiva será EX-002

Servirá para validar el Nivel 2 antes de escalar.

**Primera versión aprobada.**

La arquitectura de tres niveles ha sido validada conceptualmente mediante prototipos de EX-002.

Esto no implica que toda la biblioteca visual esté validada.
